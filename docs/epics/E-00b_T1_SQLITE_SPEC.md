# E-00b T-00b.1 — SQLite via Capacitor Plugin on Android

**Parent Epic:** E-00b: Capacitor Validation Spike
**Type:** Validation (Spike)
**Criticality:** ARCHITECTURE-GATING — this task determines whether the project commits to Capacitor or escalates to Option C

---

## 1. Goal

Validate that `@capacitor-community/sqlite` can perform full CRUD operations and enforce foreign key constraints in a Capacitor + React web app running on a physical Android device. Answer the single yes/no question:

> **Can SQLite — with foreign key enforcement — be used as the local database on Capacitor for Android?**

---

## 2. Context

### Why This Task Exists

The E-00 Technical Spike (Option A: React Native + RNW) was abandoned because `react-native-sqlite-storage` on React Native for Windows failed to honor `PRAGMA foreign_keys = ON`. The SQLite engine itself worked — 11 of 12 tests passed — but FK enforcement is non-negotiable for the application:

- `sync_log` references `devices.id` via FK
- `songs.language_id` references `languages.id` via FK
- `song_artists` has composite FK references to both `songs` and `artists`
- The LWW sync algorithm's orphan resolution (constitution Section 15.3 step 10c) assumes FK enforcement at the database level

Since Option A was rejected over this exact failure, T-00b.1 is the equivalent gate for Option D. If this task fails, the project cannot proceed with Capacitor for Android.

### Historical Note from E-00

E-00 T-00.1 ran the same 12 test cases on RNW. The package succeeded on 11/12 — the only failure was SQ-09 (FK enforcement). This test is explicitly marked **CRITICAL** in this spec.

### The Capacitor SQLite Plugin

`@capacitor-community/sqlite` is a community-maintained Capacitor plugin that wraps the platform-native SQLite implementation:
- **Android:** `android.database.sqlite.SQLiteDatabase`
- It is **not** part of Capacitor core (unlike `@capacitor/secure-storage`, `@capacitor/browser`, etc.)
- This means its reliability, maintenance cadence, and API stability carry more risk than core plugins

The plugin exposes the database via Capacitor's plugin bridge — all operations are asynchronous (return Promises). This affects the production `DatabaseConnection` interface design (E-02 T-02.3).

### Why Physical Device Required

Android emulators have differences in:
- Filesystem behavior (database file persistence path)
- WebView implementation (the emulator may use a different WebView version than the device)
- Memory constraints (emulators can allocate more RAM than physical devices)

The minimum target is Android API 26 (Android 8.0) with 2GB RAM — a mid-range device from 2022 or earlier.

## 7. Interfaces

### 7.1 DatabaseConnection (Spike Version)

```
interface DatabaseConnection {
  open(dbPath: string): Promise<void>
  close(): Promise<void>
  execute(sql: string, params?: any[]): Promise<void>
  query<T>(sql: string, params?: any[]): Promise<T[]>
  transaction<T>(fn: () => Promise<T>): Promise<T>
}
```

**Method Contracts:**

**`open(dbPath)`**
- Initializes the Capacitor SQLite plugin
- Creates or opens the database file at the given path
- Executes required pragmas: `PRAGMA foreign_keys = ON`, `PRAGMA journal_mode = WAL`, `PRAGMA synchronous = NORMAL`, `PRAGMA busy_timeout = 5000`
- Throws `ConnectionError` on failure

**`close()`**
- Closes the database connection
- Releases plugin resources
- Safe to call multiple times (idempotent)

**`execute(sql, params)`**
- Executes a single SQL statement (INSERT, UPDATE, DELETE, CREATE, DROP, PRAGMA)
- Uses parameterized queries: `?` placeholders only
- Rejects multiple statements in a single string (semicolon detection)
- Throws `ConstraintError` for FK/NOT NULL violations
- Throws `DatabaseError` for other SQL failures

**`query<T>(sql, params)`**
- Executes a SELECT query
- Returns typed array of rows
- Empty result set → empty array `[]` (not null)
- Throws `DatabaseError` on SQL failure

**`transaction<T>(fn)`**
- Begins a transaction
- Executes the callback `fn()` which receives the connection and performs operations
- If callback resolves: COMMIT
- If callback rejects: ROLLBACK and re-throw
- Nested transactions are not supported in V1

### 7.2 Error Types

```
ConnectionError    — Database cannot be opened (file permissions, plugin not available)
DatabaseError      — SQL syntax error, invalid table/column name
ConstraintError    — FK violation, NOT NULL violation, UNIQUE violation (extends DatabaseError)
```

### 7.3 Why Async?

The Capacitor plugin bridge is inherently asynchronous — every call to a native plugin returns a Promise. The interface must be async. This is a **deliberate design decision** that affects all repository implementations in E-02 and E-06:

- Electron's `better-sqlite3` is synchronous → wrapped in `Promise.resolve()`
- Capacitor's plugin is natively async → direct pass-through
- All repository methods become async (`async findById()` instead of `findById()`)
- All callers in the application layer must `await` repository calls

This is validated by the spike: if the async pattern works correctly for all 12 tests, it confirms the production architecture.

## 9. Acceptance Criteria

### 9.1 Primary Gate (All 12 Tests Must Pass)

| ID | Test Description | SQL | Pass Condition |
|----|-----------------|-----|----------------|
| SQ-01 | Open connection | `open()` | Connection object returned; no exception |
| SQ-02 | Create table | `CREATE TABLE test (id INTEGER PRIMARY KEY, value TEXT NOT NULL)` | Statement executes without error |
| SQ-03 | Insert row | `INSERT INTO test (value) VALUES ('hello')` | 1 row inserted |
| SQ-04 | Select row | `SELECT * FROM test` | Returns `[{id: 1, value: 'hello'}]` |
| SQ-05 | Update row | `UPDATE test SET value = 'world' WHERE id = 1` | 1 row updated; SELECT confirms 'world' |
| SQ-06 | Delete row | `DELETE FROM test WHERE id = 1` | 1 row deleted; SELECT returns `[]` |
| SQ-07 | Multi-insert transaction | `BEGIN; INSERT INTO test (value) VALUES ('a'); INSERT INTO test (value) VALUES ('b'); COMMIT` | Both rows committed; SELECT returns 2 |
| SQ-08 | Transaction rollback | `BEGIN; INSERT INTO test (value) VALUES ('a'); ROLLBACK` | No rows persisted; SELECT returns `[]` |
| SQ-09 | **FK violation** | See §9.2 | **Insertion REJECTED — this is the critical gate** |
| SQ-10 | Valid FK insertion | See §9.2 | Insertion succeeds |
| SQ-11 | Data persistence | Kill app process, relaunch, `SELECT * FROM test` | Previously committed data still present |
| SQ-12 | Integrity check | `PRAGMA integrity_check` | Returns "ok" |

### 9.2 SQ-09 and SQ-10 in Detail

**SQ-09 — Foreign Key Violation (CRITICAL)**

SQL sequence:
```
PRAGMA foreign_keys = ON;

CREATE TABLE parent_table (
    id INTEGER PRIMARY KEY
);

CREATE TABLE child_table (
    id INTEGER PRIMARY KEY,
    parent_id INTEGER REFERENCES parent_table(id)
);

-- Attempt to insert a child referencing a non-existent parent
INSERT INTO child_table (parent_id) VALUES (999);
```

**Expected result:** The `INSERT INTO child_table` MUST throw a `ConstraintError` or equivalent SQL error. The plugin must reject the insertion. The row must NOT appear in a subsequent `SELECT * FROM child_table`.

**If this test fails:** The plugin is not enforcing foreign keys. This is a **gating failure**. Do not proceed. Attempt the fallback package. Document the failure in `SPIKE_DECISION.md`.

**SQ-10 — Valid Foreign Key**

SQL sequence (continuing from SQ-09):
```
INSERT INTO parent_table (id) VALUES (1);

INSERT INTO child_table (parent_id) VALUES (1);
```

**Expected result:** The `INSERT INTO child_table` succeeds. `SELECT * FROM child_table` returns `[{id: 1, parent_id: 1}]`.

## 10. Testing Procedure

### 10.1 Setup (One-Time)

1. Build the Capacitor Android project: `npx cap sync && npx cap open android`
2. Connect physical Android device via USB with debugging enabled
3. In Android Studio: select device → Run 'app'
4. Verify the app launches and displays a blank screen
5. Kill the app

### 10.2 Install SQLite Plugin

```bash
pnpm --filter @collectio/capacitor-app add @capacitor-community/sqlite
npx cap sync
```

### 10.3 Deploy Spike Files

1. Create the `__spike__/` directory under `apps/capacitor/src/`
2. Create all 4 spike files as described in §4
3. Temporarily modify `main.tsx`:
   ```

   const root = createRoot(document.getElementById('root'));
   root.render(<Spike0b1Runner />);
   ```

### 10.4 Run the Spike

1. In Android Studio: Run 'app' on the connected device
2. The app launches → the spike runner component mounts
3. `Spike0b1_SQLite.ts` executes all 12 tests in sequence
4. Results display on the device screen:
   ```
   SQ-01: PASS — Open connection — 12ms
   SQ-02: PASS — Create table — 8ms
   SQ-03: PASS — Insert row — 5ms
   SQ-04: PASS — Select row — 3ms
   SQ-05: PASS — Update row — 4ms
   SQ-06: PASS — Delete row — 4ms
   SQ-07: PASS — Transaction commit — 7ms
   SQ-08: PASS — Transaction rollback — 5ms
   SQ-09: PASS — FK violation rejected — 6ms  ← CRITICAL
   SQ-10: PASS — Valid FK inserted — 5ms
   SQ-11: PASS — Data persisted after restart — 15ms
   SQ-12: PASS — Integrity check — 3ms

   Result: 12/12 passed. 0 failed. Critical: OK.
   ```

### 10.5 Test SQ-11 (Persistence) Specifically

1. Run the spike once (all 12 tests execute)
2. Do NOT close or navigate away
3. Press the device's task manager button
4. Swipe the app away (force kill)
5. Re-launch the app from the launcher
6. The spike runs again — SQ-11 must verify data from the previous run still exists

### 10.6 Verify FK Enforcement (SQ-09) Independently

If SQ-09 passes the inline test, verify independently:
1. Add a debug query after the FK violation attempt
2. `SELECT count(*) FROM child_table` — must return 0
3. If count > 0, the plugin silently inserted the orphan row — this is a **false pass**

### 10.7 Capture Results

1. On the device screen, tap "Copy Report" button
2. Paste the JSON report into `SPIKE_DECISION.md` under T-00b.1
3. Take a screenshot of the device showing all 12 results (attachment to the decision doc)

### 10.8 Cleanup

After the spike, revert `main.tsx` to its normal app entry point. Keep the `__spike__/` directory for reference.

### 10.9 If Tests Fail

1. **SQ-09 fails:** Note the exact error message. Check if `PRAGMA foreign_keys` returns 1 (verify the pragma took effect). Check Capacitor plugin version. Attempt fallback package (`capacitor-sqlite`).
2. **SQ-11 fails:** Check database file path — Capacitor may use a different path on app kill vs. background. The plugin may store data in a temporary directory that is cleared on force kill.
3. **Other failures:** Check the SQL syntax — the Capacitor plugin may have different SQL dialect support than standard SQLite. Log all errors for the decision document.
4. **Plugin initialization fails:** Check Capacitor version compatibility. `@capacitor-community/sqlite` may require specific Capacitor core versions. Check Android permissions (WRITE_EXTERNAL_STORAGE may be needed on older API levels).
