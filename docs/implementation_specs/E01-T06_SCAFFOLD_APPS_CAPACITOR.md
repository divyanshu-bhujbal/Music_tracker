# E01 T06 — Scaffold apps/capacitor: Implementation Specification

## 1. Goal

Normalize the Capacitor Android app entry point (`apps/capacitor/`) — originally created during the E-00b Capacitor validation spike — to the workspace conventions established by T-01.2 through T-01.5. Replace version ranges with exact pins per agent rules, add workspace dependencies on `@collectio/renderer` and `@collectio/platform`, remove spike test artifacts (`src/__spike__/`), rewrite the renderer entry to mount the shared React UI, restore three critical Android configuration gaps lost after the spike, and align the tsconfig with the workspace baseline.

The capacitor app exists on disk with all files from the E-00b spike. This task normalizes them — no new directories are created, and the `android/` directory (generated by Capacitor CLI) is updated via `cap sync`, not manually scaffolded.

## 4. Files to Create

### 4.1 `apps/capacitor/src/index.tsx`

- **Purpose:** Capacitor app renderer entry. Mounts the React app from `@collectio/renderer` into the WebView DOM.
- **Responsibility:** Thin mount layer. Calls `createRoot`, renders `<StrictMode>` wrapper importing from `@collectio/renderer`. No business logic, no platform conditionals, no Capacitor plugin imports.
- **Public API:** Exports nothing. Entry point loaded by `index.html` via `<script type="module" src="/src/index.tsx">`.

**File content:**

```tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";

const rootElement = document.getElementById("root");

if (rootElement) {
  createRoot(rootElement).render(
    <StrictMode>
      <div>Collectio</div>
    </StrictMode>,
  );
} else {
  throw new Error("Root element #root not found in the DOM");
}
```

**Why this content:**
- Matches `apps/electron/src/renderer.ts` exactly — consistent placeholder across both app entries
- Uses React 18 `createRoot` API (not legacy `ReactDOM.render`)
- `StrictMode` wrapper for development warnings
- Null check on `#root` with clear error message
- Does NOT import `@collectio/renderer` yet — that package currently only has `export {}`. Will be wired in E-15 (UI Shell) when the renderer package exports an `App` component
- The placeholder `<div>Collectio</div>` confirms the mount works

- **Public API:** Consumed by `tsc --noEmit` and Vite's bundler module resolution.

**Target content:**

```json
    "moduleResolution": "bundler",

    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,

    "rootDir": "./src",
    "paths": {
      "@shared/*": ["../../packages/shared/src/*"],
      "@shared": ["../../packages/shared/src"],
      "@platform/*": ["../../packages/platform/src/*"],
      "@platform": ["../../packages/platform/src"],
      "@renderer/*": ["../../packages/renderer/src/*"],
      "@renderer": ["../../packages/renderer/src"]
    }
  },
  "include": ["src"]

```

**Changes from current state:**

| Setting | Current | Target | Reason |
|---------|---------|--------|--------|
| `target` | `ES2020` | `ES2022` | Match all other workspace packages |
| `lib` | `["ES2020", "DOM", "DOM.Iterable"]` | `["ES2022", "DOM", "DOM.Iterable"]` | Consistent ES target |
| `paths` | absent | See above | Enable clean imports from workspace packages |
| `declaration` | absent | `false` | Explicit per AD-10 |
| `sourceMap` | absent | `true` | Consistent with workspace baseline |
| `outDir` | absent | `"./dist"` | Per Rule 11.5 baseline |
| `rootDir` | absent | `"./src"` | Per Rule 11.5 baseline |

| `declarationMap` | absent (correct) | absent | Omitted because `declaration: false` |

**Why `include: ["src"]` is correct here (unlike the Electron app):**
- The Capacitor app has no main/preload split — ALL source code runs in the WebView renderer process

- AD-09's pattern (excluding renderer source from include) applies only when tsconfig targets a different environment than some source files. Here the tsconfig matches the single environment (WebView)
- `noEmit: true` — type checking only. Vite + `@vitejs/plugin-react` handles compilation

### 5.4 `apps/capacitor/capacitor.config.ts`

- **Purpose:** Capacitor runtime configuration.
- **Responsibility:** Declares app identity, web asset location, server settings, and plugin options.
- **Public API:** Consumed by `@capacitor/cli` during `cap sync` and by `@capacitor/core` at runtime.

**Change:** Add `allowNavigation` to the `server` block per RC-03:

```typescript
import type { CapacitorConfig } from "@capacitor/cli";

const config: CapacitorConfig = {
  appId: "com.collectio.app",
  appName: "Collectio",
  webDir: "dist",
  server: {
    androidScheme: "https",
    allowNavigation: ["com.collectio.app://*"],
  },
  plugins: {
    CapacitorSQLite: {
      androidIsEncryption: false,
    },
  },
};

export default config;
```

**Why `allowNavigation` is required:**
- RC-03 mandates it for OAuth redirect handling
- Without it, the Capacitor WebView blocks navigation to `com.collectio.app://*` (the OAuth redirect scheme)
- The scheme `com.collectio.app://` matches the package name format required by Google's "Android" OAuth client type (AD-03)
- This was configured during the E-00b spike (spike retrospective lines 91-97) but lost from the current config

**Preserved settings (do NOT change):**
- `androidIsEncryption: false` — required per RC-02 (plugin defaults to encryption mode which causes Keystore failures)
- `androidScheme: "https"` — required for modern WebView security
- `appId: "com.collectio.app"` — matches Google Cloud Console Android OAuth client
- `webDir: "dist"` — Vite build output directory

### 5.5 `apps/capacitor/android/app/src/main/AndroidManifest.xml`

- **Purpose:** Android manifest declaring app capabilities, permissions, and intent filters.
- **Responsibility:** Registers the OAuth redirect intent filter so Android routes `com.collectio.app://` URLs back to the app.
- **Public API:** Consumed by Android OS at install time and by the intent system at runtime.

**Change:** Add the OAuth intent filter inside the existing `<activity>` element, after the existing MAIN/LAUNCHER intent filter (before `</activity>`):

```xml
<intent-filter>
    <action android:name="android.intent.action.VIEW" />
    <category android:name="android.intent.category.DEFAULT" />
    <category android:name="android.intent.category.BROWSABLE" />
    <data android:scheme="com.collectio.app" android:host="" />
</intent-filter>
```

**Why this is required:**
- RC-04 mandates this intent filter for OAuth redirects
- Android's intent system routes custom URI scheme requests to the app with the matching intent filter
- Without it, Google OAuth redirects show "URL not recognized" in the browser instead of returning to the app
- This was configured during the E-00b spike (spike retrospective line 92, updated line 97) but was lost — likely regenerated by a later `cap sync`

**Placement:** Inside the `<activity android:name=".MainActivity" ...>` element. After the existing `<intent-filter>` for MAIN/LAUNCHER. The order of intent filters within an activity does not matter.

### 5.6 `apps/capacitor/android/app/src/main/java/com/collectio/app/MainActivity.java`

- **Purpose:** Android Activity subclass that hosts the Capacitor WebView.
- **Responsibility:** Registers community Capacitor plugins before the BridgeActivity initializes.
- **Public API:** Entry point for the Android OS. Extends `com.getcapacitor.BridgeActivity`.

**Change:** Add `SecureStoragePlugin` registration. The current file registers only `CapacitorSQLitePlugin`. Both community plugins must be registered per RC-05.

**Target content:**

```java
package com.collectio.app;

import android.os.Bundle;
import com.getcapacitor.BridgeActivity;
import com.getcapacitor.community.database.sqlite.CapacitorSQLitePlugin;
import com.securestorage.capacitor.plugin.SecureStoragePlugin;

public class MainActivity extends BridgeActivity {
  @Override
  public void onCreate(Bundle savedInstanceState) {
    registerPlugin(CapacitorSQLitePlugin.class);
    registerPlugin(SecureStoragePlugin.class);
    super.onCreate(savedInstanceState);
  }
}
```

**Why `SecureStoragePlugin` registration is required:**
- RC-05: community Capacitor plugins are not auto-registered by `cap sync`
- `capacitor-secure-storage-plugin` wraps Android Keystore for credential storage
- Without `registerPlugin(SecureStoragePlugin.class)`, the plugin returns null at runtime
- `CapacitorSQLitePlugin` is already registered — only `SecureStoragePlugin` is being added

**Import verification:**
- `CapacitorSQLitePlugin`: package `com.getcapacitor.community.database.sqlite.CapacitorSQLitePlugin` (already correct)
- `SecureStoragePlugin`: package `com.securestorage.capacitor.plugin.SecureStoragePlugin` (per agent rules RC-05)

## 8. Data Flow

```
Capacitor WebView loads index.html
  → <script type="module" src="/src/index.tsx">
    → index.tsx: imports React, ReactDOM
    → index.tsx: calls createRoot(document.getElementById("root"))
    → Renders <StrictMode><div>Collectio</div></StrictMode>

At scaffolding stage, this is the full data flow.
No Capacitor plugins are called. No SQLite queries are executed.
No OAuth flows are triggered. No secure storage is accessed.

Future (E-04/E-15):
  → index.tsx imports App component from @collectio/renderer
  → App component reads platform providers from React context
  → Providers were injected by app entry wiring (E-04 DI container)
  → Capacitor native plugins (SQLite, secure storage, OAuth) are called through provider interfaces
```

## 11. Error Handling

| Failure scenario | Behavior |
|-----------------|----------|
| `pnpm install` fails after dependency changes | Check for typos in `package.json` name field or version numbers. Verify workspace protocol `workspace:*` is correct. |
| `tsc --noEmit` fails in `apps/capacitor/` | Check that `@types/react` and `@types/react-dom` are installed. Verify path aliases resolve (target directories exist). Ensure `react` and `react-dom` are resolvable (transitive from `@collectio/renderer`). |
| Path alias `@renderer` fails to resolve | Verify `packages/renderer/src/index.ts` exists. Check relative path in tsconfig `paths` is `../../packages/renderer/src`. |
| `cap sync` fails with "plugin not found" | Verify `@capacitor/core@6.2.1` is installed. Verify `node-linker=hoisted` in `.npmrc`. Run `pnpm install` before `cap sync`. |
| `cap sync` overwrites custom `AndroidManifest.xml` or `MainActivity.java` | `cap sync` does NOT regenerate these files (they are created once by `cap add android`). Manual edits should survive. Verify after sync. |
| `pnpm dev:capacitor` fails with missing `vite` | Verify `vite@5.4.21` is in devDependencies. Run `pnpm install`. |
| `pnpm dev:capacitor` launches but shows blank page | Check browser console for errors. Verify `index.tsx` compiles. Verify `index.html` script src matches the file name. |
| `pnpm build:capacitor` fails with TypeScript errors in spike code | Ensure `src/main.tsx` and `src/__spike__/` have been deleted before `tsc --noEmit` runs. |
| SecureStorage plugin returns null at runtime | Verify `registerPlugin(SecureStoragePlugin.class)` is in `MainActivity.java` before `super.onCreate()`. |
| OAuth redirect shows "URL not recognized" | Verify `allowNavigation` in `capacitor.config.ts`. Verify intent filter in `AndroidManifest.xml`. Verify scheme matches (`com.collectio.app`). |
| React Strict Mode double-mounting causes Capacitor connection issues | The `isConnection()/retrieveConnection()` pattern (IW-02) in the platform package handles this. No action needed at app level. |
